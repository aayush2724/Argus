# Argus evaluation protocol

Revision 4 preserves the Revision 2 study design and Revision 3 scoring clarifications. This document specifies planned experiments. No Argus benchmark results exist yet.

Use the official evaluator with the original v0.1 dataset and an independently generated recent slice. The official evaluator groups by repository and commit and passes `to_analyzer` to the agent's analyze interface. Verify the exact checked-out version and behavior in M0. Record evaluator and generator Git SHAs, original and derived dataset SHA-256 hashes, data sources and extraction dates, generator settings, snapshot commits and run configuration. [Official SastBench repository](https://github.com/RivalSecurity/sastbench) · [Generator documentation](https://github.com/RivalSecurity/sastbench/tree/main/dataset_generation) · [Paper](https://arxiv.org/abs/2601.02941)

| Element | Preregistered rule |
|---|---|
| Split | Freeze seeded repository-level groups in M0, normalize aliases and check fork overlap. Target about 150 dev findings. Keep held-out labels with the scorer. Use dev for tuning and gates, then freeze prompts, budgets, model settings and test manifest before scoring. Preserve the Revision 2 research design of a 600-finding stratified headline test subset, three seeds/configuration and a full held-out run as resources allow. Report actual sample sizes, exclusions, class counts and seed support. |
| Parity | Give both classes exactly the official `to_analyzer` payload plus permitted checkout reads. Keep labels, source, outer finding IDs, rule identifiers/text, severities and prohibited metadata away from agents, prompts and tools. Apply identical preprocessing, context and effort rules. No rule recovery, future history, external CVE lookup or product filters. |
| Leakage | Run a preregistered payload-only logistic probe with repo-disjoint training and scoring. Compare against a chance baseline with uncertainty and publish the result. Investigate material signal before interpreting benchmark claims. Validate label-bearing metadata exclusion and checkout isolation with fixtures and sampled manifests. |
| Prediction and errors | Map `needs_review` to positive in primary surfaced metrics and to negative in sensitivity analysis. Report abstention rate. Preserve official evaluator error records and report their count and coverage. Verify the pinned evaluator error-denominator policy in M0 and record it alongside the official metrics. Also report an all-sample sensitivity with errors treated as unsurfaced, and require matched inclusion policies in comparisons. |
| Ranking | Define `positive_score` as the model's explicit ranking of true-positive likelihood, independent of confidence in its chosen verdict. Capture it before abstention mapping. Compute PR-AUC as average precision over the preregistered scored set, report coverage and omit when valid comparable scores or both classes are absent. Do not fabricate scores for errors or turn positive confidence into a calibrated probability. Use reliability plots only for a separately specified probability experiment. |
| Metrics | MCC primary. Also report precision, recall, F1, average precision where defined, abstentions, evidence validity, p50/p95 latency, failure rates, cost per attempted finding and cost per surfaced ground-truth positive. Include retries in spend, report missing usage and zero denominator metrics as undefined. Use repository-cluster bootstrap 95% CIs and paired cluster bootstrap for ablations. Report per-language with symbol-tool coverage and per-CWE family, with sample sizes and sparse groups flagged. |
| Baselines and comparisons | Include all-positive, all-negative, random at base rate, Argus single-shot, Argus tool loop and supported official bundled agents. Compare tool modes on the same provider/model and samples with fixed prompts where applicable, seed policy, budgets and evaluator version. Compare models with the same protocol and matched common constraints, recording any capability differences. Label unsupported configurations or mismatches and avoid head-to-head claims. A direct paper comparison requires its full dataset, model, agent/scoring conventions and matched protocol. |
| Recent slice | Use the official generator and freeze a slice after a documented model cutoff. Report original and recent results separately with slice composition and uncertainty. For cross-model comparisons use a shared slice after the latest verified cutoff. Unknown cutoffs permit a recent-slice sensitivity result with contamination status unverified. Treat slice gaps as descriptive because sample composition can differ. |
| Reproduction | Save engine commit, prompt/contracts hashes, rules and container versions, exact provider/model and disclosed version or weights, effective generation parameters, seeds, budgets, usage, prices and raw evaluator outputs. Pin scoring inputs. Run a 20-finding dev regression in CI with deterministic replay and fixed metric/cost tolerances. Run a live dev smoke separately with a hard cap and disclose nondeterminism. |

## Experimental sequence and gates

1. M0 pins the evaluator and generator, verifies official score/error semantics and proves the adapter can run with the product API, DB and UI down. Use approximately five samples for a plumbing smoke and a one-month recent window for generator feasibility. Record generator prerequisites, negative generation/filtering policies and excluded or failed repositories. Construct splits using canonical repository families. Keep scorer-only stratification and manifests outside the analyzer.
2. M2 qualifies each proposed provider/model with contract fixtures and a bounded live or local dev smoke for JSON output, required tool behavior, context limit handling, token fields and refusal/error normalization. If a capability is unavailable, report the unsupported cell. Run an approximately ten-finding Argus evaluator smoke, then the single-shot dev gate. Retain the Revision 2 target of MCC above random with uncertainty, at least matching the comparable bundled single-shot baseline and invalid evidence below 10%. Report an inconclusive or failed gate and investigate before making performance claims.
3. M3 uses paired repository-cluster intervals for tool-loop minus single-shot MCC. The research gate is a 95% interval entirely above zero or matched MCC with at least 30% lower cost per finding on the same cost basis. Preregister a matching tolerance before the dev comparison. Zero or unknown comparable costs make the cost gate unevaluable. If neither branch passes, document a negative or inconclusive result and revise the research claim before test scoring. Keep engineering security gates independent.
4. M6 freezes the test recipe before any held-out scoring. Include all-positive and all-negative, seeded random at dev prevalence, single-shot, tool-loop, and bundled agents where comparable. Test retrieval variants by changing only the declared retrieval policy. M8 expands repeats, sample sizes and post-cutoff work only when budget and provenance support it. Publish actual coverage, limitations and negative results.

## Evidence and experiment interpretation

Measure location validity as valid citations divided by all proposed citations, recording findings with any invalid citation and separate missing-evidence counts. Score verdict correctness against official labels with the declared mapping. The dataset's negative class is approximate, as described by its authors. Review evidence relevance separately on a seeded sample stratified by decision and language. Reviewers use a rubric for whether a citation supports the stated source, propagation, sanitization, sink or precondition, and distinguish relevant, irrelevant and ambiguous. Blind reviewers to model identity and labels where practical. Publish sample selection, assessor count, disagreements and single-assessor limitations. A real line or linked edge cannot establish exploitability on its own. [SastBench paper](https://arxiv.org/abs/2601.02941)

Freeze bootstrap unit, resample count/seed, sparse-strata policy and degenerate MCC behavior before test scoring. Report undefined intervals when resamples lack enough class support. For repeated seeds retain results per seed and preserve repository pairing when pooling. Version the exact average-precision implementation and denominator rules. Equivalence checks use protocol/dataset/split hashes, inclusion policies, tool/context and budget settings. Mark profiles as intended experimental factors. When unsupported conditions prevent comparability, show the runs separately without ranking.

## Cost and artifacts

Use mocks in CI and small dev-only live experiments. Resume only when dataset, evaluator, code, inputs, prompt, model version, provider settings, scoring and replay semantics match. Reuse complete same-run checkpoints with intact usage journals. For retrospective metric replay use recorded outputs and clearly separate it from new inference. A shared warm cache is a declared experimental condition and must be controlled or disclosed. Record observed versus estimated cost, coverage and unknown calls, with monetary caps and pre-reserved worst-case estimates before dispatch. Free tiers are verified before use. Track local wall time and peak memory separately from API charges. A default paid cap of USD 0 applies.

Publish an immutable manifest and summary with run ID, checksums, metrics and relevant confidence intervals. Keep sensitive artifacts and labels in the scorer workspace, with separate sanitized public artifacts. The Model Evaluation Lab reads imported records and labels mismatches. Include a replay command in the final write-up so interviewers can regenerate the displayed figures locally.
