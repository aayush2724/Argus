# Argus threat model

Revision 4 planned controls and acceptance checks.

## Boundaries and enforcement

Treat repository text, filenames, manifests, scanner results, tool parameters and model output as untrusted. Never run target application code, tests, builds, scripts or package installs. Disable Git hooks, submodules, filters and external helpers for ingestion. Keep networked fetching confined to a trusted ingestion component with approved sources. Use a detached single-commit snapshot and verify no parent/future objects are reachable in the benchmark workspace. Mount only the exported tree into analysis workers. Keep `.git` and evaluator metadata outside the filesystem visible to tools, including nested or case-aliased equivalents.

- Use OS-level isolation for scanners and repository-reading tools/indexers, with an unprivileged account, read-only snapshot mount, no network, narrowly scoped scratch space, dropped capabilities, and no host sockets or credentials. Bind the model client to configured provider endpoints only. Treat Docker control as trusted orchestration and keep its socket outside analysis containers. The benchmark container may need evaluator/provider connectivity while analysis tools run with separate OS enforcement. Validate a compatible mechanism in M0.
- Resolve tool paths relative to a trusted root, reject absolute paths, traversal components, symlinks and special files, and prevent check/open races with filesystem-constrained opens or an immutable exported snapshot. Limit bytes, lines, search matches, pattern cost, file count, parser work, checkout/disk size, CPU, memory and process count. Use explicit executable and argument allowlists, deadlines and bounded reads across all phases. Fail closed when isolation or cleanup cannot be established.
- Expose only `read_file`, `grep`, `list_dir`, `read_manifest`, plus Tree-sitter `find_symbol` and `callers` for JS/TS and Python. Other languages use file tools only. Validate all arguments and normalize all returned paths. Treat tool output as delimited untrusted data. Ignore repository-supplied instructions and keep prompts, scanner config and tool authorization in trusted code. Redact secrets from every outbound model input, including snippets, manifests, tool responses and initial context, and sanitize logs and reports.
- Validate each evidence location deterministically against the immutable snapshot and its line bounds. Exclude invalid citations, count them and downgrade a positive verdict lacking valid evidence to `needs_review`. Citation validity checks location integrity. Review rationale and evidence relevance separately in failure analysis.
- Exercise path and symlink escapes, absolute paths, races, `.git` aliases, oversized files, resource limits, malicious content, redaction and process isolation with inert fixtures. Measure verdict flips between matched clean and prompt-injection fixtures.

## Actors and trust zones

The attacker may control a repository, scanner-visible text, a drive-by browser origin or data returned by a provider. A malicious local administrator or Docker daemon is outside the local-first trust assumption. The API and job supervisor are trusted orchestration. The scanner, indexer and read-only tool runner get a read-only snapshot and separate bounded scratch space. The provider client gets only sanitized input and a credential scoped to its configured provider. The evaluator and its labels form a separate trusted scoring zone.

Start with a tested Linux/Docker deployment. For the product use pinned, unprivileged containers with read-only root and snapshot, no network, no host sockets, dropped capabilities, no-new-privileges, isolated scratch with limits, and CPU, memory, process and wall-time ceilings. For SastBench prove an equivalent tool-process boundary under the pinned upstream topology in M0, with a networked evaluator-facing process and an isolated scanner/index/tool worker. Do not fall back to shared unrestricted execution if the platform cannot enforce it. Never expose the Docker daemon to analyzed processes.

| Surface | Control and adversarial acceptance |
|---|---|
| Ingestion | Approve local roots and explicit remote hosts. Reject local transports and redirects outside policy. Disable implicit Git behavior. Snapshot into private storage, reject symlinks, special files, traversal and reserved paths during export, enforce total byte limits. Verify fixtures cannot read a host canary. |
| Scanner / parser | Run pinned trusted scanner tooling with fixed rules and no network. Limit output, time, process tree, memory and scratch. Test timeout and forced cleanup. Scanning repository text executes Argus tooling only. Target application code is never launched. |
| Tools and model | Allow only schema-validated operations on the snapshot. Bound every read/search/call. Reject arbitrary commands and unknown tool names. Treat comments, README text and faux role messages as data. Test misleading comments, fake system prompts, forged citations and tool parameter manipulation with inert fixtures. |
| Privacy and telemetry | Default to local models for private work. Remote use requires informed opt-in and dated review of provider retention, training/data-use terms and project permissions. Minimize/redact snippets before every call. Audit sinks with secret canaries. Redaction can miss novel secrets, so restrict what is eligible for upload. |
| API / UI | Loopback and same-origin host/origin checks, bounded body and pagination, allowlisted paths, escaped text and safe paths/links. Test hostile display names, payloads and filenames. Avoid user-supplied shell commands or file-download paths. |
| Artifacts and DB | Private directories, bounded schema-validated records, artifact digests and fenced ingestion. Never mount evaluator metadata into tools. Test stale attempts, corrupted reports and rollback. |

Distinguish denied unauthorized calls, unexpected accesses and actual boundary violations. A boundary violation blocks release. Record verdict flips, invalid evidence and agent failures separately from isolation outcomes using matched benign/adversarial fixtures and fixed model settings. Document residual risk from runtime/daemon flaws, evolving prompt injection, model errors, resource pressure and incomplete redaction. Acceptance covers the tested environment and fixtures.
