# Argus application database

PostgreSQL is the durable application store. The Node application alone owns every table below. Express and its job controller share service-layer transactions through Drizzle. Python has no connection, credentials or migration role. A local Node command imports evaluation summaries. Use UUIDs for public IDs, UTC timestamptz, constrained statuses, nonnegative counters, finite numeric scores, fixed precision currency estimates and explicit nullable fields for unknown usage. Reject records outside their parent scope using composite foreign keys where redundant IDs are present.

| Table | Primary and foreign keys | Columns and constraints | Indexes | Retention |
|---|---|---|---|---|
| `repositories` | UUID ID | Source type, canonical approved source, display name, archived time, timestamps. Unique type/source. | Created time + ID, active list | Archive by default, restrict deletion with scans. |
| `scan_runs` | UUID ID, repository FK | State, idempotency key, canonical request hash, snapshot digest/ref, config digest and normalized manifest, deadline, cancel timestamp, phase/counters, terminal timestamps, final digest. Unique repository/key. Completed requires final digest. | Repository + created time + ID, status + created time + ID | Keep submission key as long as run remains replayable. |
| `scan_jobs` | scan ID as PK/FK, nullable current attempt FK scoped to same scan | Available time, scheduler disposition (ready, leased, cleanup, closed), attempt count, cleanup owner/expiry. Pointer is null before claim, kept through cleanup, cleared on scheduling or terminalization. Public scan state lives in scan_runs. | Partial (available_at, scan ID) for ready jobs, cleanup expiry | Keep with parent scan. |
| `scan_attempts` | UUID ID, job/scan FK | Ordinal, owner, trusted execution handle, heartbeat/lease, start/end, outcome, last event sequence, bounded diagnostic. Unique scan/ordinal and scan/ID. At most one active attempt per job. | Partial lease expiry for active attempts, scan + ordinal | Keep outcomes and timing with scan. Purge workspaces separately. |
| `findings` | UUID ID, scan FK | Stable finding key, scanner, disposition, title, description, CWE array, typed primary location, bounded secondary locations and scanner metadata. Unique scan/key and scan/ID. | Scan + ID, scan + scanner/ID and disposition/ID as needed | Keep with report. |
| `verdicts` | Finding ID as PK/FK | Decision, decision confidence, optional positive score, summary, preconditions, CWE, fix direction, bounded evidence graph. Check scores in [0,1]. | Decision + finding ID | Keep with report. |
| `evidence` | Verdict FK + citation ordinal as PK | Relative path, start/end line, role, validation status, optional redacted excerpt and note. Ordered positive line bounds. Persist citeable locations only for validated evidence. | PK supports ordered reads | Keep with report. Retain minimal excerpts only. |
| `model_usage` | Attempt ID + call ID as PK, scoped scan and optional finding FKs | Stable logical finding key before final publication, provider/model, call ordinal, request ID, status, reserved bound, reported tokens, actual/estimated cost, currency and timestamps. Call IDs unique per attempt. Pending/settled/indeterminate states. | Scan + timestamp, scan + finding key | Preserve all attempts and indeterminate costs with run. |
| `agent_tool_calls` | Attempt ID + call ID as PK, scoped scan and optional finding FKs | Stable finding key, tool name, outcome, duration, timestamp, bounded redacted diagnostic. | Scan + finding key + timestamp | Purge call details on shorter diagnostic retention, keep counters. |
| `evaluation_runs` | UUID ID | Unique external run key, artifact digest, provider/model/version, dataset/split hashes, evaluator and engine commits, protocol fingerprint, manifest, status and times. | Dataset + finished time + ID, provider/model + finished time + ID | Keep summaries and provenance references. Preserve raw runs in research artifact store. |
| `evaluation_results` | Evaluation FK + metric key + slice kind + slice key + policy key as PK | Nullable value, numerator/denominator when applicable, scoped sample counts, CI bounds/method, units, undefined reason. Overall uses explicit slice key. | Metric + slice kind, evaluation PK for reads | Keep with evaluation run. |
| `failure_events` | UUID ID, scoped scan/attempt and optional finding FKs | Stable event ID unique per attempt, phase, failure code, transient/terminal classification, timestamp and sanitized bounded detail. | Scan + timestamp, code + timestamp | Expire verbose detail before summaries. |

Use typed columns for scheduling, accounting and common filters. JSONB is limited to versioned manifests, secondary scanner-specific locations/metadata, graph presentation data and bounded diagnostics. Foreign keys enforce scan membership for attempts and published findings. Link pre-publication usage, tool and failure events via the stable finding key, then backfill optional finding IDs in the result transaction. Use restricted parent deletion by default and scoped leaf cascades for explicit offline maintenance. Cited excerpts and artifacts have configurable local retention and per-run size limits. When excerpts expire, surface the citation and expiration status. Keep digest, metrics and accounting separately from temporary bytes.

## Transactions and migrations

- Enqueue the scan and job together. Claims, retries, terminal cleanup and publication maintain both records under the service lock order. Use constraints and affected row checks for stale attempts. Enforce graph references, legal transitions, evidence requirements and cross-row run totals in application transactions where row checks cannot express them. [Job protocol](ARCHITECTURE.md#durable-execution-protocol)
- Reconcile usage by immutable attempt/call identity. Replays compare payloads. Transitions from reserved to settled or indeterminate are guarded. A late verified settlement can be applied by the controller during reconciliation, with an auditable correction. Released reservation never resurrects a dispatch authorization.
- Keep ordered Drizzle migrations in `apps/api`, including reviewed SQL for partial indexes and row-lock claims where ORM generation is insufficient. Pin DB image and tooling during M0. Use a separate migration command with a migration lock and a restricted runtime role. Pause the worker for local schema changes. Prefer additive changes, explicit bounded backfills and later constraint enforcement. Back up the local DB before destructive changes and prefer forward fixes or restoring a verified backup.
- Test fresh install, upgrade from the preceding shipped schema, duplicate idempotency keys, scoped FKs, transaction rollback, stale writers and two competing claimers against real PostgreSQL. Reject unsupported DB schema on startup. Preserve final result and evaluator artifact compatibility independently of schema migration.
